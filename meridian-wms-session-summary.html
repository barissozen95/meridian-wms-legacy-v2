Application Overview

Meridian WMS is a legacy Warehouse Management System REST API built on .NET Framework 4.8 with ASP.NET Web API 2. It serves logistics and manufacturing distributors by tracking product stock across physical warehouses and fulfilling customer orders end-to-end.

The application is intentionally structured as a 2016-era enterprise .NET app — no dependency injection, synchronous EF6 calls, raw SQL string concatenation, and Windows/IIS-only hosting. It is the "before" codebase used in the IBM Bob .NET Modernization Workshop.

Product Catalogue

Manage SKUs with name, category, unit weight, unit price, and active/inactive status.

Inventory Management

Per-warehouse stock with on-hand and reserved quantities, bin locations, and low-stock alerting.

Order Fulfilment

Create customer orders with line items, allocate stock from the default warehouse, then ship.

Shipment Tracking

Record outbound shipments with carrier, tracking number, origin warehouse, and total weight.

Inventory Search

Free-text search over product names via raw ADO.NET against the same SQL Server database.

Stock Adjustment

Manual delta-based quantity adjustments with a guard against negative on-hand stock.

Software Architecture Diagram

The application is a single-project, three-layer monolith: an HTTP / Controller layer (ASP.NET Web API 2), a Service layer (plain C# classes), and a Data Access layer (EF6 WmsDbContext + raw ADO.NET). All layers are wired together with new; configuration is read ad-hoc via ConfigurationManager.

Order Lifecycle

Orders progress through up to four statuses, stored as free-text strings on the Order.Status property. Transitions are enforced by guard conditions inside OrderService.

Pending
1 · Creation

Order created with validated line items. UnitPriceAtOrder captured from current product price. OrderNumber generated as ORD-yyyyMMddHHmmss.

Trigger: POST /api/orders
Allocated
2 · Allocation

Reads DefaultWarehouseCode from config. Checks available stock per line. Increments QuantityReserved for each InventoryItem.

Trigger: POST /api/orders/{id}/allocate
Shipped
3 · Shipment

Decrements QuantityOnHand and QuantityReserved per line. Computes total weight. Inserts a Shipment record with carrier + tracking number.

Trigger: POST /api/orders/{id}/ship
Cancelled
4 · Cancelled

Defined as a known status value in the model's comment, but no endpoint or service method implements cancellation. This is documented intent, not live code.

No trigger — not implemented

Guard Conditions & Error States

  • OrderService.Allocate() Order status is not "Pending" → throws "Only Pending orders can be allocated."
  • OrderService.Ship() Order status is not "Allocated" → throws "Only Allocated orders can be shipped."
  • OrderService.Allocate() QuantityOnHand − QuantityReserved < line.Quantity → throws "Insufficient stock for product {id}"
  • OrderService.CreateOrder() ProductId not found in DB → throws "Unknown product: {id}"
  • InventoryService.AdjustQuantity() QuantityOnHand + delta < 0 → throws "Quantity on hand cannot be negative."

Identified Legacy Issues & Modernisation Targets

These are the intentional legacy issues present in the codebase, identified during analysis, which make it a strong modernisation candidate for the workshop:

  • No async/await All EF6 calls are synchronous on every request thread, blocking under load.
  • SQL Injection InventoryService.SearchByProductName builds a raw SQL string via string concatenation: "WHERE p.Name LIKE '%" + nameFragment + "%'" — no parameterisation.
  • No Dependency Injection All services and DbContext instances are created with new inside controllers and services — untestable and unswappable.
  • Local DateTime DateTime.Now used for all timestamps instead of DateTime.UtcNow, risking timezone inconsistencies across environments.
  • Magic-String Status Order.Status is a plain string instead of a typed enum, enabling silent typos and preventing compile-time safety.
  • Ad-hoc Config Configuration read ad-hoc inside service methods via ConfigurationManager.AppSettings[…] — no typed options pattern, no centralised config object.
  • Windows / IIS Coupling System.Web, Global.asax, and IIS Express coupling block cross-platform hosting on Linux/macOS and prevent containerisation.
